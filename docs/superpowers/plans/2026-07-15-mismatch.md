# `mismatch` v1 — Plan d'implémentation (chantier B)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (ou subagent-driven-development).
> Steps use checkbox (`- [ ]`) syntax.

**Goal:** Le dossier apprend à dire qu'un lieu répond MAL à une priorité déclarée, sans que ce soit
éliminatoire. Un lecteur qui a pesé « les espaces naturels » à 3 sur une commune médiocre lit enfin un
constat comparatif honnête, au lieu de « critère non examiné ». Couverture : 9 → 19 critères sur 28.

**Architecture:** Un rôle de fait `mismatch` et deux outcomes de règle (`mismatch`, `neutral`), au-dessus
d'une brique de **rang national à deux bornes** précalculée dans l'index (jamais sur la shortlist). Une
**fabrique de règles** produit les 10 règles de position. Une **section propre** dans le dossier et une
**orientation `arbitration`** dérivée d'un ensemble matériel de mismatchs. Bump du prompt et re-passage de
la sonde.

**Tech Stack:** TypeScript, Next.js, `node --test`, l'index national `data/comparateur-index.json` (bâti
par `scripts/build-comparateur-index.mjs`).

## Global Constraints

- **Le dossier ne lit JAMAIS `ModuleFacts.scores` pour un fait opposable** : `subScore` applique des replis
  (`?? 0`, `?? 100`) qui transforment une donnée absente en verdict. C'est le `?? 0` que le chantier A a
  démonté. Le rang se bâtit sur la **valeur brute nullable**, et `rawValue === null` → `uncertain`.
- **Le rang est NATIONAL** (34 788 communes), jamais calculé sur la shortlist du comparateur.
- **Un mismatch s'appuie sur un percentile ASSUMÉ** : jamais un jugement absolu (« insuffisant »,
  « manque »), toujours une position relative avec l'univers de comparaison nommé (« de France »).
- **On dit la fraction la plus LARGE que la donnée garantit**, jamais la plus frappante : « les 20 % »
  exige `rankHigh <= 0,20`, « le quart » `rankHigh <= 0,25`, « les 5 % » `rankHigh <= 0,05`.
- **`EXTREME_SHARE = 0,20`**, convention de produit nommée et versionnée (`MISMATCH_CONVENTIONS_VERSION`).
- **Un intervalle d'ex æquo à cheval sur un seuil rend `neutral`**, jamais un mismatch de position.
- **La matérialité suit le POIDS DÉCLARÉ** (poids 3 → `structuring`, sinon `secondary`), **jamais
  `decision_critical`**.
- **L'orientation `arbitration` dérive d'un ENSEMBLE MATÉRIEL**, jamais d'un booléen `mismatchCount > 0`.
- **Pas de tiret cadratin.** Pas de `?? 0` sur une donnée nullable.
- Après chaque tâche : `node --test src/lib/*.test.ts src/lib/decision/*.test.ts` vert, `npx tsc --noEmit`
  rend 0. La sonde ne repasse qu'à la Task 8 (le prompt ne bouge qu'à ce moment).

## Task 1 : La classification de position (pure)

**Files:**
- Create: `src/lib/decision/mismatch-facts.ts`, `src/lib/decision/mismatch-facts.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export const MISMATCH_CONVENTIONS_VERSION = "mismatch-conv-1";
  export const EXTREME_SHARE = 0.2;

  // Le rang, ORIENTÉ (0 = le pire, 1 = le meilleur), à DEUX bornes pour gérer les ex æquo.
  export type RankBand = { low: number; high: number };

  export type RelativeCriterionFact = {
    key: string;              // PreferenceKey
    rawValue: number | null;  // la valeur BRUTE nullable. null = non lu.
    band: RankBand | null;    // null = non lu (rang non calculable)
    universe: "communes_france";
    distributionVersion: string;
  };

  export type PositionVerdict = "mismatch" | "satisfied" | "neutral" | "uncertain";

  export function classifyPosition(fact: RelativeCriterionFact): PositionVerdict;
  export function rankPhrase(high: number): string; // « les 5 % », « le cinquième », « le quart »…
  ```

**Notes de conception :**
- `low` = part des communes STRICTEMENT moins favorables ; `high` = part moins favorables OU à égalité.
  Donc `low <= high`, et le groupe d'ex æquo occupe `[low, high]`.
- **Défavorable non ambigu** : `high <= EXTREME_SHARE` (tout le groupe d'ex æquo est dans le bas). Favorable
  non ambigu : `low >= 1 - EXTREME_SHARE`. Sinon `neutral`.
- `rankPhrase` ne surestime JAMAIS : elle rend la plus large fraction `f ∈ {0,05 ; 0,10 ; 0,20 ; 0,25}` telle
  que `high <= f`. Une commune à `high = 0,18` se dit « les 20 % » (0,20), jamais « les 5 % ».

// src/lib/decision/mismatch-facts.ts
// LA DOCTRINE DU MISMATCH. Lib PURE : aucune I/O, aucun LLM.
//
// Un mismatch dit une POSITION RELATIVE, et l'assume. Là où une incompatibilité oppose au lecteur un fait
// du MONDE (« à 240 km de la mer que vous exigez »), un mismatch dit « parmi les communes les moins bien
// dotées » : le percentile n'est plus caché derrière un verdict inventé, il EST le constat.
//
// LE RANG A DEUX BORNES, et c'est ce qui gère honnêtement les ex æquo. Si 83 % des communes partagent la
// même valeur, l'intervalle [low, high] traverse tout le bas du classement, et « parmi les 20 % » serait
// faux. On ne tranche alors pas : neutral.

export const MISMATCH_CONVENTIONS_VERSION = "mismatch-conv-1";
export const EXTREME_SHARE = 0.2; // convention de produit : l'extrême, c'est le cinquième de la distribution

export type RankBand = { low: number; high: number }; // orienté : 0 = le pire, 1 = le meilleur

export type RelativeCriterionFact = {
  key: string;
  rawValue: number | null;
  band: RankBand | null;
  universe: "communes_france";
  distributionVersion: string;
};

export type PositionVerdict = "mismatch" | "satisfied" | "neutral" | "uncertain";

export function classifyPosition(f: RelativeCriterionFact): PositionVerdict {
  // UNE DONNÉE ABSENTE N'EST PAS UNE POSITION : jamais un rang inventé.
  if (f.rawValue == null || f.band == null) return "uncertain";
  // Extrême DÉFAVORABLE non ambigu : TOUT le groupe d'ex æquo est dans le bas.
  if (f.band.high <= EXTREME_SHARE) return "mismatch";
  // Extrême FAVORABLE non ambigu.
  if (f.band.low >= 1 - EXTREME_SHARE) return "satisfied";
  // Centre, ou intervalle à cheval sur un seuil : on ne tranche pas.
  return "neutral";
}

// On dit toujours la fraction la plus LARGE que la borne garantit, jamais la plus frappante.
const FRACTIONS: { max: number; label: string }[] = [
  { max: 0.05, label: "les 5 % de communes" },
  { max: 0.1, label: "les 10 % de communes" },
  { max: 0.2, label: "les 20 % de communes" },
  { max: 0.25, label: "le quart des communes" },
];
export function rankPhrase(high: number): string {
  const f = FRACTIONS.find((x) => high <= x.max);
  return f ? f.label : "le quart des communes";
}
```

  `not_applicable` ne produisent aucun fait.
- Poids < 2 → `not_applicable` (non déclarée). Le critère absent de `rankBands` → `rawValue: null` →

// src/lib/decision/mismatch-rules.ts
// LA FABRIQUE DES RÈGLES DE MISMATCH (position relative). PURE.
//
// Une règle par critère de qualité à distribution saine. Elle lit le rang précalculé (rankBands), JAMAIS
// ModuleFacts.scores : subScore applique des replis (?? 0, ?? 100) qui transforment une donnée absente en
// verdict, et c'est le mensonge que le chantier A a démonté.
import type { DecisionRule, RuleEvaluation, MismatchFact, EvidenceRef, ModuleFacts } from "./decision-fact.ts";
import type { UserProject } from "../user-project.ts";
import { preferenceWeight } from "./project-view.ts";
import type { PreferenceKey } from "../comparateur-vie.ts";
import { PREFERENCE_LABELS } from "../comparateur-labels.ts";
import {
  classifyPosition, rankPhrase, MISMATCH_CONVENTIONS_VERSION, type RelativeCriterionFact,
} from "./mismatch-facts.ts";

const territoireHref = "/rapport/quartier";

// Les 10 critères de la v1, vérifiés à distribution saine sur 34 788 communes.
export const MISMATCH_KEYS: PreferenceKey[] = [
  "nature", "acces_ecoles", "acces_soins", "acces_culture", "acces_transports",
  "faible_dependance_auto", "croissance_demographique", "vie_locale", "cadre_calme", "viabilite_emploi",
];

function relativeFact(f: ModuleFacts, key: PreferenceKey): RelativeCriterionFact {
  const band = f.rankBands?.[key] ?? null;
  return {
    key, rawValue: band ? 1 : null, band, universe: "communes_france",
    distributionVersion: MISMATCH_CONVENTIONS_VERSION,
  };
}

function makeMismatchRule(key: PreferenceKey): DecisionRule {
  const id = `territoire.mismatch-${key}`;
  const label = PREFERENCE_LABELS[key] ?? key;
  return {
    id,
    module: "territoire",
    evaluate: (f: ModuleFacts, p: UserProject): RuleEvaluation => {
      const ret = (outcome: RuleEvaluation["outcome"], facts: MismatchFact[], reason: string): RuleEvaluation =>
        ({ ruleId: id, projectKeys: [key], outcome, facts, reason });

      if (preferenceWeight(p, key) < 2) return ret("not_applicable", [], "priorité non déclarée");
      const rel = relativeFact(f, key);
      const verdict = classifyPosition(rel);

      if (verdict === "uncertain") return ret("uncertain", [], "rang non calculable");
      // satisfied et neutral : examinés, mais SILENCIEUX (aucune carte). La couverture monte quand même.
      if (verdict !== "mismatch") return ret(verdict, [], verdict === "satisfied" ? "extrême favorable" : "position neutre");

      const band = rel.band!;
      const tier = preferenceWeight(p, key) >= 3 ? "structuring" : "secondary";
      const ev: EvidenceRef = {
        factId: `scores.${key}`, module: "territoire", label: `Territoire · ${f.nom}`,
        observedValue: `parmi ${rankPhrase(band.high)}`, grain: "commune", href: territoireHref,
      };
      const fact: MismatchFact = {
        id: `${f.insee}:mismatch-${key}`, ruleId: id, sourceFactIds: [`scores.${key}`], module: "territoire",
        role: "mismatch", projectKey: key, materialityTier: tier,
        topic: label,
        // COMPARATIF, jamais un jugement absolu. L'univers est nommé (« de France »), et le lien au projet
        // explicite. « moins bien » ne dit pas « mauvais » : il dit « moins qu'ailleurs ».
        statement: `Vous avez placé ${label} parmi vos priorités. Sur cet indicateur, ${f.nom} se situe parmi ${rankPhrase(band.high)} les moins favorables de France. Cela répond moins bien à cette dimension de votre projet, sans rendre ${f.nom} incompatible avec lui.`,
        basis: { kind: "relative_position", rankLow: band.low, rankHigh: band.high, universe: "communes_france" },
        evidence: [ev],
      };
      return ret("mismatch", [fact], "position relative défavorable");
    },
  };
}

export const MISMATCH_RULES: DecisionRule[] = MISMATCH_KEYS.map(makeMismatchRule);
```

Le cœur du calcul :

```js
// RANG NATIONAL À DEUX BORNES pour les 10 critères de mismatch (v1). Calculé sur la VALEUR BRUTE nullable
// de chaque critère, JAMAIS sur subScore (qui replie ?? 0 / ?? 100 : une donnée absente y deviendrait un
// verdict). Une commune sans valeur brute n'entre pas dans la distribution et n'a pas de bande -> uncertain.
// Chemins VÉRIFIÉS contre une entrée réelle de l'index (2026-07-15). Plusieurs valeurs brutes sont déjà des
// percentiles (nature.score, ecoles.score…) : bâtir un rang sur un percentile est redondant mais exact (le
// rang d'un rang est le même rang). Ce qui compte, c'est que la valeur soit NULLABLE (une commune sans la
// clé n'a pas de bande), là où subScore la repliait en verdict.
const MISMATCH_RAW = {
  nature: (c) => c.nature?.score ?? null,
  acces_ecoles: (c) => c.ecoles?.score ?? null,
  acces_soins: (c) => c.vivpct?.apl ?? null,
  acces_culture: (c) => c.culture?.score ?? null,
  acces_transports: (c) => c.transport?.desserte ?? null,
  faible_dependance_auto: (c) => (c.mobilite?.dependance == null ? null : 100 - c.mobilite.dependance), // dépendance basse = mieux
  croissance_demographique: (c) => c.demographie?.croissance ?? null,
  vie_locale: (c) => c.vieLocale?.score ?? null,
  cadre_calme: (c) => (c.densite == null ? null : -c.densite), // densité basse = mieux -> on inverse le signe
  viabilite_emploi: (c) => (c.emploi == null ? null : 0.6 * c.emploi.taille + 0.4 * c.emploi.diversite),
};
for (const c of communes) c.rankBands = {};
for (const [key, get] of Object.entries(MISMATCH_RAW)) {
  const vals = communes.map(get).filter((v) => v != null).sort((a, b) => a - b);
  const N = vals.length;
  const lowIdx = (v) => { let lo = 0, hi = N; while (lo < hi) { const m = (lo + hi) >> 1; if (vals[m] < v) lo = m + 1; else hi = m; } return lo; };
  const highIdx = (v) => { let lo = 0, hi = N; while (lo < hi) { const m = (lo + hi) >> 1; if (vals[m] <= v) lo = m + 1; else hi = m; } return lo; };
  for (const c of communes) {
    const v = get(c);
    if (v == null || N === 0) continue; // pas de bande -> uncertain
    c.rankBands[key] = { low: lowIdx(v) / N, high: highIdx(v) / N };
  }
}
```
