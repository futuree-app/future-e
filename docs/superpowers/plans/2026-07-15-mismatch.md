# `mismatch` v1 — Plan d'implémentation (chantier B)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (ou subagent-driven-development).
> Steps use checkbox (`- [ ]`) syntax.

**Goal:** Le dossier apprend à dire qu'un lieu répond MAL à une priorité déclarée, sans que ce soit
éliminatoire. Un lecteur qui a pesé « les espaces naturels » à 3 sur une commune médiocre lit enfin un
constat comparatif honnête, au lieu de « critère non examiné ». Couverture : 9 → 19 critères sur 28.

**Architecture:** Un rôle de fait `mismatch` et deux outcomes de règle (`mismatch`, `neutral`), au-dessus
d'un **rang national à deux bornes** bâti sur `signatureScore` (l'ordre canonique du comparateur, déjà
nullable : le dossier ne re-dérive aucune formule, les deux moteurs ne peuvent donc pas diverger). Une
**fabrique de règles** produit les 10 règles de position. Une **section propre**, deux nouvelles
orientations (`arbitration`, `neutral`), un bump du prompt et un re-passage de la sonde.

**Tech Stack:** TypeScript, Next.js, `node --test`, l'index national `data/comparateur-index.json` (67 Mo,
enrichi par des scripts `populate-*`, JAMAIS régénéré par `build-comparateur-index.mjs`).

## Global Constraints

- **Le dossier ne re-dérive AUCUNE formule de critère.** Le rang se bâtit sur `signatureScore(key, commune)`
  (comparateur-vie), qui est l'ordre canonique du comparateur ET déjà nullable (il neutralise les `?? 0` /
  `?? 100` de `subScore`). Bâtir un rang « maison » ferait recommencer la divergence que le chantier A a
  fermée (deux moteurs, deux définitions d'un même critère).
- **Aucune valeur brute inventée.** `RelativeCriterionFact` porte la vraie valeur (`signatureScore`) OU
  `null`. Jamais `rawValue: 1` pour « satisfaire un type ». `band == null` ⇔ `rawValue == null` ⇔ `uncertain`.
- **La provenance n'est PAS `scores.*`** (le dossier n'y touche pas) : `evidenceKeys = ["relativePosition.${key}"]`.
- **Le rang est NATIONAL** (34 788 communes, sur les seules qui ont la donnée), jamais sur la shortlist.
- **Deux versions distinctes.** `MISMATCH_CONVENTIONS_VERSION` (la doctrine : `EXTREME_SHARE`, ex æquo) et
  `MISMATCH_DISTRIBUTION_VERSION` (le millésime des données classées). Une évolution de `EXTREME_SHARE` ne
  recalcule pas la distribution ; une MAJ INSEE/BPE, si.
- **Un mismatch s'appuie sur un percentile ASSUMÉ** : jamais un jugement absolu (« insuffisant », « manque »),
  toujours une position relative avec l'univers nommé (« de France »).
- **On dit la fraction la plus LARGE que la donnée garantit** : « les 20 % » exige `rankHigh <= 0,20`.
- **`EXTREME_SHARE = 0,20`**, convention de produit nommée et versionnée.
- **La bande à deux bornes PORTE les ex æquo** : un intervalle à cheval sur un seuil rend `neutral`.
- **Le POIDS gouverne la MATÉRIALITÉ, jamais l'EXAMINABILITÉ.** Priorité absente → `not_applicable`. Poids 1
  → examinée (couverture monte), mais **silencieuse** (aucune carte, aucun effet sur l'orientation). Poids 2
  → `secondary`. Poids 3 → `structuring`. **Jamais `decision_critical`.**
- **L'orientation `arbitration` dérive d'un ENSEMBLE MATÉRIEL de faits** (`run.facts`, pas les évaluations),
  jamais d'un booléen.
- **`neutral` (orientation) ≠ `favorable` ≠ `indeterminate`** : examiné, données disponibles, mais aucun
  signal marqué. `favorable` exige un signal favorable MATÉRIEL.
- **Pas de tiret cadratin.** Pas de `?? 0` sur une donnée nullable.
- Après chaque tâche : `node --test src/lib/*.test.ts src/lib/decision/*.test.ts` vert, `npx tsc --noEmit`
  rend 0. La sonde ne repasse qu'à la Task 8.

```ts
// src/lib/decision/mismatch-facts.ts
// LA DOCTRINE DU MISMATCH. Lib PURE : aucune I/O, aucun LLM.
//
// Un mismatch dit une POSITION RELATIVE, et l'assume. Là où une incompatibilité oppose un fait du MONDE
// (« à 240 km de la mer que vous exigez »), un mismatch dit « parmi les communes les moins bien dotées » :
// le percentile n'est plus caché derrière un verdict inventé, il EST le constat.
//
// LE RANG A DEUX BORNES, et c'est ce qui PORTE les ex æquo. Si 300 communes partagent la même valeur, la
// bande [low, high] est large, et une commune à cheval sur un seuil rend neutral : la bande ne prétend
// jamais à une précision qu'un score arrondi n'a pas.

export const MISMATCH_CONVENTIONS_VERSION = "mismatch-conv-1"; // la DOCTRINE (extrême, ex æquo)
export const MISMATCH_DISTRIBUTION_VERSION = "mismatch-dist-2026-07-15"; // le MILLÉSIME des données classées
export const EXTREME_SHARE = 0.2;

export type RankBand = { low: number; high: number };

export type RelativeCriterionFact = {
  key: string;
  rawValue: number | null;
  band: RankBand | null;
  universe: "communes_france";
  distributionVersion: string;
};

export type PositionVerdict = "mismatch" | "satisfied" | "neutral" | "uncertain";

function bandValide(b: RankBand | null): b is RankBand {
  return (
    b != null &&
    Number.isFinite(b.low) && Number.isFinite(b.high) &&
    b.low >= 0 && b.high <= 1 && b.low <= b.high
  );
}

export function classifyPosition(f: RelativeCriterionFact): PositionVerdict {
  // Une donnée absente ou une bande invalide n'est JAMAIS une position : jamais un rang inventé.
  if (f.rawValue == null || !bandValide(f.band)) return "uncertain";
  if (f.band.high <= EXTREME_SHARE) return "mismatch"; // tout le groupe d'ex æquo est dans le bas
  if (f.band.low >= 1 - EXTREME_SHARE) return "satisfied";
  return "neutral"; // centre, ou intervalle à cheval sur un seuil
}

const FRACTIONS: { max: number; label: string }[] = [
  { max: 0.05, label: "les 5 % de communes" },
  { max: 0.1, label: "les 10 % de communes" },
  { max: 0.2, label: "les 20 % de communes" },
  { max: 0.25, label: "le quart des communes" },
];
export function rankPhrase(high: number): string {
  return (FRACTIONS.find((x) => high <= x.max) ?? { label: "le quart des communes" }).label;
}

// LA TABLE DE PHRASES. PREFERENCE_LABELS n'est pas grammatical dans « Vous avez placé {…} parmi vos
// priorités ». topic = le SUJET nommé (<= 70 car., cf. assertFactValid). projectPhrase = la priorité, tournée
// pour l'ouverture. indicator = ce sur quoi porte la comparaison.
export const MISMATCH_LABELS: Record<string, { topic: string; projectPhrase: string; indicator: string }> = {
  nature: { topic: "les espaces naturels", projectPhrase: "la proximité des espaces naturels", indicator: "l'accès aux espaces naturels" },
  acces_ecoles: { topic: "l'accès aux collèges et lycées", projectPhrase: "l'accès aux collèges et lycées", indicator: "l'accès aux collèges et lycées" },
  acces_soins: { topic: "l'accès aux soins", projectPhrase: "un bon accès aux soins", indicator: "l'accès aux soins" },
  acces_culture: { topic: "l'accès à la culture", projectPhrase: "l'accès à une offre culturelle", indicator: "l'accès à l'offre culturelle" },
  acces_transports: { topic: "l'accès au train", projectPhrase: "l'accès au train et aux gares", indicator: "la desserte ferroviaire" },
  faible_dependance_auto: { topic: "la dépendance à la voiture", projectPhrase: "une faible dépendance à la voiture", indicator: "la possibilité de se déplacer sans voiture" },
  croissance_demographique: { topic: "la trajectoire démographique", projectPhrase: "un territoire qui gagne des habitants", indicator: "la trajectoire démographique" },
  vie_locale: { topic: "la vie locale", projectPhrase: "une vie locale animée", indicator: "l'intensité de la vie locale" },
  cadre_calme: { topic: "le cadre calme", projectPhrase: "un cadre calme", indicator: "le calme du cadre de vie" },
  viabilite_emploi: { topic: "le bassin d'emploi", projectPhrase: "un bassin d'emploi dynamique", indicator: "le dynamisme du bassin d'emploi" },
};
```

## Task 3 : La fabrique de règles (et la doctrine du poids)

**Files:** Create `src/lib/decision/mismatch-rules.ts`, `src/lib/decision/mismatch-rules.test.ts`

**Interfaces:**
- Consumes: `classifyPosition`, `rankPhrase`, `MISMATCH_LABELS` (Task 1) ; `MismatchFact` (Task 2).
- Produces: `export const MISMATCH_RULES: DecisionRule[]` (10) ; `export const MISMATCH_KEYS: PreferenceKey[]`.

**LA DOCTRINE DU POIDS (gravée) :**
```
poids 0 (absente)  -> not_applicable
poids 1 (mineure)  -> examinée, mais SILENCIEUSE : outcome mismatch/satisfied/neutral SANS carte,
                      et un mismatch de poids 1 ne produit AUCUN MismatchFact (donc pas d'arbitrage)
poids 2            -> carte secondary
poids 3            -> carte structuring
```
Le poids gouverne la MATÉRIALITÉ, jamais l'EXAMINABILITÉ : un mismatch de poids 1 reste un `mismatch`
(couverture +1), il est seulement non matériel.

```ts
// LA FABRIQUE DES RÈGLES DE MISMATCH (position relative). PURE.

// Elle lit le rang précalculé (rankBands), bâti sur signatureScore : l'ORDRE CANONIQUE du comparateur, déjà
// nullable. Le dossier ne re-dérive AUCUNE formule, donc les deux moteurs ne peuvent pas diverger.
import type { DecisionRule, RuleEvaluation, MismatchFact, EvidenceRef, ModuleFacts } from "./decision-fact.ts";
import type { UserProject } from "../user-project.ts";
import { preferenceWeight } from "./project-view.ts";
import type { PreferenceKey } from "../comparateur-vie.ts";
import {
  classifyPosition, rankPhrase, MISMATCH_LABELS, MISMATCH_DISTRIBUTION_VERSION,
  type RelativeCriterionFact,
} from "./mismatch-facts.ts";

const territoireHref = "/rapport/quartier";

export const MISMATCH_KEYS: PreferenceKey[] = [
  "nature", "acces_ecoles", "acces_soins", "acces_culture", "acces_transports",
  "faible_dependance_auto", "croissance_demographique", "vie_locale", "cadre_calme", "viabilite_emploi",
];

function relativeFact(f: ModuleFacts, key: PreferenceKey): RelativeCriterionFact {
  const band = f.rankBands?.[key] ?? null;
  // La VRAIE valeur (le centre de la bande suffit à classifyPosition ; on ne fabrique jamais un nombre pour
  // « satisfaire un type »). null quand il n'y a pas de bande -> uncertain.
  return {
    key,
    rawValue: band ? band.low : null,
    band,
    universe: "communes_france",
    distributionVersion: MISMATCH_DISTRIBUTION_VERSION,
  };
}

function makeMismatchRule(key: PreferenceKey): DecisionRule {
  const id = `territoire.mismatch-${key}`;
  const lab = MISMATCH_LABELS[key]!;
  return {
    id,
    module: "territoire",
    evaluate: (f: ModuleFacts, p: UserProject): RuleEvaluation => {
      const ret = (outcome: RuleEvaluation["outcome"], facts: MismatchFact[], reason: string): RuleEvaluation =>
        ({ ruleId: id, projectKeys: [key], outcome, facts, reason });

      const weight = preferenceWeight(p, key);
      if (weight === 0) return ret("not_applicable", [], "priorité non déclarée");

      const verdict = classifyPosition(relativeFact(f, key));
      if (verdict === "uncertain") return ret("uncertain", [], "rang non calculable");

      // LE POIDS GOUVERNE LA MATÉRIALITÉ, JAMAIS L'EXAMINABILITÉ. satisfied/neutral sont toujours
      // silencieux. Un mismatch de poids 1 est examiné (l'outcome remonte, la couverture monte) mais ne
      // produit AUCUNE carte : il n'est pas matériel, et ne déclenchera pas d'arbitrage.
      if (verdict !== "mismatch" || weight < 2) {
        return ret(verdict, [], verdict === "mismatch" ? "mismatch mineur, silencieux (poids 1)" : `position ${verdict}`);
      }

      const band = f.rankBands![key]!;
      const tier = weight >= 3 ? "structuring" : "secondary";
      const ev: EvidenceRef = {
        factId: `relativePosition.${key}`, module: "territoire", label: `Territoire · ${f.nom}`,
        observedValue: `parmi ${rankPhrase(band.high)} les moins favorables`, grain: "commune", href: territoireHref,
      };
      const fact: MismatchFact = {
        id: `${f.insee}:mismatch-${key}`, ruleId: id, sourceFactIds: [`relativePosition.${key}`], module: "territoire",
        role: "mismatch", projectKey: key, materialityTier: tier,
        topic: lab.topic,
        statement: `Vous avez placé ${lab.projectPhrase} parmi vos priorités. Sur ${lab.indicator}, ${f.nom} se situe parmi ${rankPhrase(band.high)} les moins favorables de France. Cela répond moins bien à cette dimension de votre projet, sans rendre ${f.nom} incompatible avec lui.`,
        basis: { kind: "relative_position", rankLow: band.low, rankHigh: band.high, universe: "communes_france" },
        evidence: [ev],
      };
      return ret("mismatch", [fact], "position relative défavorable");
    },
  };
}

export const MISMATCH_RULES: DecisionRule[] = MISMATCH_KEYS.map(makeMismatchRule);
```

```js
const KEYS = [/* MISMATCH_RANK_KEYS */];
const report = [];
const bandsByInsee = new Map();
for (const key of KEYS) {
  const vals = communes.map((c) => signatureScore(key, c)).filter((v) => v != null).sort((a, b) => a - b);
  const N = vals.length;
  if (N < communes.length * 0.5) { console.error(`REFUS: ${key} couvre ${N}/${communes.length}`); process.exit(1); }
  if (vals[0] === vals[N - 1]) { console.error(`REFUS: ${key} distribution constante`); process.exit(1); }

  const highIdx = (v) => { let lo = 0, hi = N; while (lo < hi) { const m = (lo + hi) >> 1; if (vals[m] <= v) lo = m + 1; else hi = m; } return lo; };
  let tieMax = 0;
  for (const c of communes) {
    const v = signatureScore(key, c);
    if (v == null) continue;

    tieMax = Math.max(tieMax, high - low);
```
